### 2. グループ鍵交換とアイテム名暗号化フロー実装 ✅

**Purpose**: 共有アイテム名を保存時に暗号化し、表示時に復号する運用を確立する。

**Background**: 新規作成アイテムは暗号化される一方、既存アイテムの平文残存や鍵変更時再暗号化の抜けがあった。

**Problem / Root Cause**:

保存経路の一部で暗号化処理が未接続、また鍵変更検知条件が狭く既存平文回収が漏れていた。

```dart
// ❌ 問題パターン
// - 保存時暗号化が適用されない経路がある
// - 鍵フィンガープリント不変時に再暗号化が走らない
```

**Solution**:

- `HybridSharedListRepository` の保存経路で暗号化を強制
- 取得経路で復号を統一
- 鍵変更時の全件再暗号化を追加
- 鍵不変でも平文検出時は再暗号化するフォールバックを追加
- 再暗号化中フラグをローカル/Firestoreで管理
- 旧暗号データ復号との後方互換を維持

```dart
// ✅ 修正後の方針
// save: addSingleItem/updateSingleItem で暗号化
// read: get/watch 経路で復号
// rotate or plaintext-detected: 全件再暗号化 + inProgress フラグ更新
```

| group_key_exchange_service_test.dart   | Pass      |

## 🐛 発見された問題

### 既存アイテムが平文のまま残る問題 ✅

- **症状**: 新規アイテムは暗号化されるが、既存アイテムは平文 `name` が残る
- **原因**: 鍵変更検知時のみ再暗号化が走る設計で、鍵不変時の平文回収が漏れていた
- **対処**: 平文検出時の再暗号化フォールバックと再暗号化中フラグを追加
- **状態**: 修正完了（実データ確認は翌日継続）

### エミュレーター容量不足による起動失敗 ✅

- **症状**: prod/dev起動時に `INSTALL_FAILED_INSUFFICIENT_STORAGE`
- **原因**: `/data` 使用率が高く空き容量不足
- **対処**: 既存アプリ削除後に再インストール
- **状態**: 修正完了

## 💡 技術的学習事項

### 暗号化導入時は保存・取得・移行の3経路をセットで実装する

**問題パターン**:

```dart
// ❌ 保存時だけ暗号化し、既存データ移行を未実装
```

**正しいパターン**:

```dart
// ✅ 保存時暗号化 + 読み出し時復号 + 平文検出時の再暗号化
```

**教訓**: セキュリティ機能は新規データだけでなく既存データの移行戦略と進捗フラグ管理まで含めて設計する必要がある。
